# 发布审查 · 2026-10-18

审查对象为从当前运行来源选取的 QQ / 微信桥接源码，整理在独立发布目录。原运行目录、微信 DLL、DSH profile、聊天数据未修改；原 Git 历史未复制到公开仓库。

## 已确认并修复

- QQ 锁文件与依赖声明不一致，npm ci 失败：重新解析并锁定依赖。
- npm 扫描发现 MCP SDK 高危、proxy-addr 严重公告：更新修复版本并回归。
- 微信安全预设缺失时降级默认会话：改为失败即停止；不再直接复用缺少安全标记的旧映射。
- 微信硬编码个人群号、昵称、数据目录和 Python 路径：去除，使用示例或环境变量。
- 微信跨目录导入 QQ 客户端/配置：改为独立 lib 和模块配置；补入 DSH 安装目录中的微信插件。
- 原生表情 wrapper 自动新建 ID 重试：删除；按消息意图派生稳定 ID，未知结果不回落。
- 发送 CLI 缺少白名单复核、非法过期时间绕过：提交前即时检查，非法/过期拒绝。
- 子进程启动错误未处理、图片仅 HTTP 200 被判成功、本机 requests 走系统代理：补异常/超时、业务 ret 校验、禁用环境代理。
- 表情索引指向库外文件：真实路径检查，拒绝目录穿越和指向库外的链接。
- sticker 配置没有进入 CONFIG：接入实际配置。
- 旧测试期待已移除的 cwd 模板变量、把 volatile 字段当字符串：按当前协议修正，没有恢复不安全旧行为。

## 维护债务

QQ bridge.js 接近 1.2 万行，集中状态与职责过多；微信 loop.mjs 约 900 行。原目录混有一次性探针、迁移和修复脚本。本次以文件清单排除这些运维遗留，保留业务算法；后续按配置、会话、发送策略、控制台分步拆分并维持回归。

外部 hook 的全网卡监听、手工对象生命周期、无明确许可证仍需独立处理，hook 不在分发包。微信文本/图片没有与原生表情相同的持久幂等承诺。Codex 后端不在此次当前运行来源中。

## 验证口径

测试统计和归档摘要见 release-validation.json / SHA256SUMS。静态与离线测试不等于端到端验收。本轮不接生产 QQ/微信发送，不把历史实机成功冒充发布副本验收，也不保证零漏洞。
